# 多组件架构

采用单仓库、多独立包的结构。当前先实现框架，以 Hello 模块演示；keyboard 保留设计，日历和图表按实际需求增加。

## 依赖方向

宿主使用 loader、ui 和所需组件。loader/ui 依赖 core；node-adapter 仅用于电脑上的参考示例。core 不反向依赖组件；组件之间不隐式初始化彼此。

统一组件约定包括 ID、组件版本、接口版本、运行时要求、资源根目录和 dispose。键盘的 open、词库、候选等能力属于 keyboard，不进入所有组件的公共接口。

## 分发

源码分发：从 GitHub 克隆源码，使用本地包依赖，由使用方 Falcon 工具链编译框架入口和前台提示进 AMR。各包版本独立，目前保持 private、未发布 npm；包名不能视为 npm 上已经可用。

公共目录分发：GitHub catalog 提供精确版本的组件清单和文件；应用带宿主适配和 loader，缺失时前台提示下载。组件全部校验后按版本原子安装到公共目录。源码版 Hello 用于验证普通 ESM 路径；QuickJS 字节码需要单独生成匹配产物。框架版本、组件版本、接口版本、数据版本和运行时要求分别记录。

组件使用宿主 Vue/Falcon 渲染环境。资源路径从组件根目录解析，组件不覆盖宿主 setViewPort、不调用业务服务、不假设浏览器 DOM 或 Node API 存在。

## 生命周期

组件安装文件可以共享；模块实例和会话数据通常仍在各应用进程内。模块缓存可复用，输入状态须隔离。close 清理会话，dispose 清理组件资源；不承诺模块或字节码可以卸载。

## 当前证据

核心行为使用 Node 18 测试，Node 参考适配可执行完整安装/加载。前台提示与 Falcon 示例可使用本地 aiot-vue-cli 1.0.32 进行 Vue/生产字节码编译检查。包外加载、外部样式注册、真机触控及多固件兼容尚未验证，需记录目标固件和实测结果。
