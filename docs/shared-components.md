# 设备公共目录方案（待验证）

目录示例：

```text
/userdisk/components/falcon-components/
  keyboard/
    1.0.0/
      manifest.json
      runtime/<profile>/keyboard.js.bin
      assets/
      dictionaries/
  calendar/
    <version>/
```

这不是已安装目录；根路径由宿主配置。manifest 中规划记录组件 ID、版本、接口版本、所需 Falcon/QuickJS 配置、入口文件、依赖和资源列表。格式先在最小加载实验中验证，再固定为公开契约。

## 加载顺序

1. 宿主选择组件和兼容版本。
2. loader 获取描述信息并选择适用运行时产物。
3. 宿主模块加载适配加载入口，确认组件接口和资源定位。
4. 当前应用挂载 UI，创建独立会话。
5. 关闭时清理会话资源，模块缓存可保留。

文件权限按 root 可读处理。仍需验证包外路径是否可被 Falcon 运行时接受、依赖如何解析、编译后样式如何注册、资源是否可从外部目录读取，以及 QuickJS 字节码版本/配置是否匹配。

不直接复制另一个应用的构建产物并假设可用，也不直接替换 QuickJS 全局模块加载器破坏宿主内置模块。若原加载器不支持公共目录，先提出范围明确的宿主适配方案。

## 更新

各组件使用不可变版本目录；完整安装后再让宿主选择新版本。进行中的会话继续使用其原版本，不覆盖已加载文件或承诺热替换模块。保留旧版本供兼容应用使用，清理策略随后定义。

## 最小验证

先加载一个无第三方依赖的外部模块，再加载含样式和资源的最小 Vue 组件；分别检查普通 JS 和生产字节码路径。随后使用两个独立示例应用验证同目录加载和状态隔离。

记录型号、固件、Falcon/QuickJS 配置、工具链、安装与启动方式、产物哈希、结果和关键日志。验证成功前，只宣称设计方案，不能宣称设备共享动态加载已经支持。
